用五大領域（人口、安全、健康、社會參與、數位）看見每個里的高齡風險，讓里長、局處與在地團體知道「哪個里、哪個問題最急、先做什麼」。

## 要解決的問題

臺灣已進入超高齡社會，但高齡資源分配多以「區」為單位，看不到區裡面哪個**里**最需要幫忙。里長最了解在地，卻缺少數據說服局處、申請經費；局處握有資料，卻分散在不同機關，且多半只公開到區級。

## 怎麼解決

| 功能 | 給誰用 | 做什麼 |
|---|---|---|
| 全市該做什麼 | 局處、市府 | 456 個里依風險排序；最該先做的 3 件事、資源先給哪一區、風險地圖 |
| 我的里 | 里長 | 本里在五個面向的位置、這里需要你做的事、行動清單 |
| 里長文書 | 里長 | 一鍵產生：經費申請佐證、路口改善陳情、熱浪關懷訊息、**100 日行動計畫** |
| 政策試算 | 局處 | 9 項政策（獨居關懷、巡迴醫療、健檢到據點、走出家門、耐震撤離、路口安全、陰涼步行路、防詐、數位）調整力度，看高風險里會減少多少 |
| 指標與公式 | 所有人 | 36 項指標的公式、資料來源、資料等級，全部公開 |
| 匯入資料 | 機關 | 貼上一里一列的 CSV 即可替換；資料只留在瀏覽器，不上傳 |
| 100 日建置計畫 | 決策者 | 全市頁直接看到落地步驟與需要的合作單位 |

**指標架構**：對齊國發會「超高齡社會五大領域風險評估指標」草案（36 項指標）。
**判定方式**：點數法（依國發會計畫建議，最弱 10% 記 1 點）或四分位法（依全球高齡觀察指數 GAWI 準則），可切換。

## 現況：哪些是真的、哪些待補

| 狀態 | 項數 | 說明 |
|---|---|---|
| 已匯入（開放資料計算） | 10 | 人口、長者行人事故、人行道樹蔭、大眾運輸、關懷據點、Wi-Fi 熱點等 |
| 推估 | 1 | 人行道缺樹蔭比例（樹冠寬推估 8 m） |
| 有開放資料，待下載 | 5 | 土壤液化潛勢、醫事機構座標、各里出生死亡、遷入遷出、屋齡 |
| 機關資料，需申請 | 12 | 獨居、低收中低收、身障、失能、健檢、癌篩、流感疫苗、志工、終身學習等 |
| 區級資料套用到里 | 8 | 氣候、空品、醫事人員、長照床位等 |

沒有資料的指標顯示「待提供」，**不計分**，不會被當成 0。

## SWOT 分析

### S 優勢（Strengths）
- **對齊國家框架**：指標直接採國發會五大領域草案，局處不用重新討論「要看什麼」。
- **看到里**：開放資料大多只到區，本專案把能算的指標都算到 456 個里。
- **透明可重現**：每項指標的公式、來源、資料等級都寫在頁面上；分析程式公開。
- **直接能用**：里長文書一鍵產生經費申請、陳情、關懷訊息、100 日行動計畫，不是只有圖表。
- **零成本、易部署**：單一 HTML 檔，不需資料庫；Cloudflare 免費方案即可上線。
- **個資友善**：只收里級加總、少於 3 人遮蔽、匯入資料不離開瀏覽器。
- **能長出解方**：已長出「走這條！」，證明看見可以變成行動。

### W 劣勢（Weaknesses）
- **一半以上指標待補**：36 項中 12 項需向機關申請、8 項只有區級，排名目前主要由人口、事故、樹蔭等少數指標決定。
- **只有臺北市**：資料處理流程依臺北市資料格式寫成，換城市要調整。
- **草案會變**：國發會指標仍是草案，定稿後公式可能要改。
- **資料更新靠手動**：目前沒有自動排程，人口、事故需要重新跑程式。
- **沒有使用者驗證**：還沒有里長實際使用過，文書內容是否合用未經確認。
- **地圖是示意**：全市地圖用方格依方位排列，不是實際里界。

### O 機會（Opportunities）
- **超高齡社會政策正在推動**：國發會指標計畫、長照 3.0 都需要「看到里」的工具。
- **里長需要佐證**：申請經費、陳情需要數據，本工具直接產生文字。
- **開放資料持續增加**：data.taipei 已有關懷據點、Wi-Fi、樹木等資料，可再接入。
- **可擴大到其他縣市**：指標是全國框架，換資料即可複製。
- **跨局處合作的共同語言**：同一張表讓社會局、衛生局、交通局看同一個里。
- **解方可持續長出來**：每個高風險面向都可以像「走這條！」一樣，長出一個專門的解方。

### T 威脅（Threats）
- **機關資料拿不到或很慢**：B 級資料需各局處同意，申請流程可能超過 100 日。
- **被誤用為排名或標籤**：里被列為「高風險」可能引起里長或居民反彈，需說明這是找資源，不是評分。
- **個資與資安疑慮**：即使只用加總，機關仍可能擔心再識別風險。
- **沒有維運單位**：黑客松結束後若沒人接手，資料會過期。
- **與既有系統重疊**：局處可能已有內部儀表板，需說明本工具的定位是「里長看得懂、拿得走」。

### SWOT 對策

| 策略 | 做法 |
|---|---|
| SO（用優勢抓機會） | 以國發會框架為共同語言，邀社會局、衛生局在試辦里一起用 |
| WO（用機會補劣勢） | 先接 5 項已有開放資料的指標，再用試辦成果申請機關資料 |
| ST（用優勢擋威脅） | 頁面寫清楚「只收加總、少於 3 遮蔽、不上傳」，降低個資疑慮；用語從「排名」改為「優先」 |
| WT（降低最壞情況） | 第 100 日前一定要確定維運單位；資料改自動更新，避免沒人管就過期 |

### 影響力 × 關注度

| | 關注度低 | 關注度高 |
|---|---|---|
| **影響力高** | 資訊局、工務局 → **保持滿意**：給清楚的資料需求，不增加負擔 | 社會局、國發會、民政局 → **重點經營**：每階段都要見面確認 |
| **影響力低** | 大學、友善單位 → **定期告知** | 里長、據點、長輩家屬 → **密切溝通**：他們是使用者，回饋決定成敗 |

## 100 日落地計畫

**目標**：第 100 日時，資料補齊到可用、至少 2 個里實際用過、確定維運單位，正式上線。

### 第 1–30 日：資料到位、找到夥伴

| 週 | 工作 | 負責／合作 |
|---|---|---|
| 1 | 確認主責單位（建議社會局長青福利科），成立 3–5 人工作小組 | 社會局 |
| 1–2 | 下載 5 項已有開放資料的指標並匯入 | 開發團隊、資訊局 |
| 1–3 | 送出 12 項機關資料申請（只要里級加總、少於 3 人遮蔽、不要名冊） | 社會局、衛生局、民政局、長照管理中心、警察局 |
| 2–3 | 選 2–3 個試辦里（建議從排名前段且里長有意願的里挑選） | 區公所、里長 |
| 3–4 | 與國發會計畫團隊確認指標草案的最新版本 | 國發會 |

**完成標準**：資料申請全部送出；試辦里確定；工作小組成立。

### 第 31–60 日：試辦、收回饋

| 週 | 工作 | 負責／合作 |
|---|---|---|
| 5–6 | 匯入已取得的機關資料，重算 456 里風險排序 | 開發團隊 |
| 5–8 | 試辦里使用「我的里」、里長文書、100 日行動計畫 | 里長、里幹事 |
| 6–8 | 每兩週訪談一次里長：哪些文字直接能用、哪些要改、還缺什麼 | 工作小組 |
| 7–8 | 依回饋修改文書範本與用語（例：「高風險」改為「優先」） | 開發團隊 |

**完成標準**：至少 2 個里實際使用；至少 1 份文書實際送出（經費申請或陳情）。

### 第 61–100 日：修正、上線、交接

| 週 | 工作 | 負責／合作 |
|---|---|---|
| 9–10 | 指標與計分方式對齊國發會定稿 | 國發會、開發團隊 |
| 9–11 | 資料改為每月自動更新 | 開發團隊、資訊局 |
| 10–12 | 上線前弱點掃描、個資保護評估 | 資訊局、維運單位 |
| 12–13 | 整理試辦成果，提出擴大到其他里的經費需求 | 社會局 |
| 13–14 | 交接維運單位：主機、更新流程、問題回報窗口 | 維運單位 |

**完成標準**：正式網址上線；維運單位與更新流程確定；試辦成果報告完成。

### 成效指標（KPI）

| 指標 | 第 100 日目標 |
|---|---|
| 有資料的指標數 | 由 10 項提高到 20 項以上 |
| 實際使用的里 | ≥ 2 個 |
| 實際送出的里長文書 | ≥ 2 份 |
| 機關資料申請 | 12 項全部送出，取得 ≥ 6 項 |
| 維運單位 | 確定 1 個 |

### 風險與對策

| 風險 | 對策 |
|---|---|
| 機關資料 100 日內拿不到 | 先用 5 項開放資料補強；頁面維持「待提供、不計分」，不影響使用 |
| 里長不想被標為高風險 | 用語改為「優先」；先邀請有意願的里長，不強制 |
| 沒有單位願意維運 | 第 1 週就確認主責單位；工具零成本、單檔，降低接手門檻 |
| 國發會定稿與草案差異大 | 公式集中在程式一處，可快速調整 |

## 部署（Cloudflare Workers）
- 網址：`https://zheli-needs-you.hondao2026.workers.dev`；頁尾「走這條！」自動連到同一子網域的 `silver-safe-walk`
- Cloudflare：Workers & Pages → Create → Import a repository → 選本 repo → Deploy；之後推送到 `main` 會自動重新部署
- 帳密（選用）：沒設定時公開瀏覽；要登入就在 Settings → Variables and Secrets 新增 Secret `DEMO_USER`、`DEMO_PASS`
- 更新時記得把 `public/index.html` 同步複製到 silver-safe-walk 的 `public/zheli/index.html`
